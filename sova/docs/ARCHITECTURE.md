# TrustForge Architecture

## Overview
TrustForge is an air-gapped, CPU-only AI workbench designed for inspection and compliance work. It runs strictly locally with no external cloud dependencies, enabling secure processing of sensitive internal documents.

## Technology Stack
- **Backend:** FastAPI (Python), SQLite (relational data), ChromaDB (vector store embedded in-process), Ollama (local LLM serving).
- **Frontend:** React 18, Vite, Tailwind CSS.
- **Hardware Profile:** Optimized for 16GB RAM CPU-only deployment (no GPU required).

## Core Data Flow

1. **Ingestion (Document Upload)**
   - Users upload PDFs or DOCX files to a project.
   - The backend reads the document (`documents_router.py`).
   - OCR is applied via Tesseract if it is a scanned PDF/image.
   - Text is embedded using `sentence-transformers` and stored locally in the embedded ChromaDB instance (`app/core/rag.py`).

2. **Task Creation & AI Workbench**
   - A user submits a query/task in the Workbench.
   - The task is dispatched in the background (`orchestrator.py`), where the agent manages state.
   - **Agent Loop:**
     - **Plan & Route:** The prompt is routed to the appropriate local model (e.g., `qwen2.5:3b-instruct` for reasoning, `qwen2.5-coder` for coding).
     - **Retrieve (RAG):** Context is queried from ChromaDB.
     - **Tool Execution:** The LLM can optionally use tools (e.g., `calculator`, `sandbox`).
     - **Verification:** Grounding logic verifies that cited facts and numbers in the response exist in the source document (`verifier.py`).
     - **Artifact Generation:** A drafted finding or compliance table is generated.

3. **Human Approval (Four-Eyes Principle)**
   - Tasks that modify state or generate critical artifacts require human approval.
   - The task is locked in `PENDING_APPROVAL` status.
   - A separate user with appropriate permissions (e.g., `REVIEWER`) reviews the artifact and signs off.

4. **Deliverable Generation**
   - Once approved, the final artifact is generated (e.g., a signed DOCX report) embedding the verifications, compliance table, and signature.

## Security & Isolation
- **Air-Gapped Operation:** A socket-level monkey patch (`security_monitor.py`) intercepts all network calls, blocking any connections to non-loopback IPs and guaranteeing zero exfiltration.
- **Role-Based Access Control (RBAC):** Users are assigned roles (`ADMIN`, `USER`, `REVIEWER`). Access to projects and artifacts is constrained by project membership and role.
- **Code Sandbox:** Python code generated by the agent is executed in an isolated subprocess (`sandbox.py`) with forbidden imports (e.g., `os`, `sys`) checked at the AST level.
- **Audit Logging:** Tamper-evident hash-chained audit logs record every sensitive action (`db.py`).

## File Structure
- `sova/backend/app/`: FastAPI application code.
  - `core/`: DB setup, auth, RAG, security monitor.
  - `routers/`: API endpoints (auth, tasks, documents, audit, system).
  - `agent/`: Orchestrator, tools (sandbox, calculator, verifier).
- `sova/frontend/src/`: React frontend.
  - `pages/`: Dashboard, Workbench, Documents, Audit, Security.
  - `api/`: Axios client configuration.
- `sova/scripts/`: Setup and demonstration scripts.
